# Consume the shared compiled-build suite in csk

## Description
Add an independent Python consumer for every shared compiled-build interoperability case. The consumer must exercise csk behavior against the external suite root and derive no expected values from Curator or from implementation-local fixtures.

## Scope
Work in the csk repository after TASK-260720-12r55p, TASK-260720-3pemm6, and TASK-260720-2g7avf. Own the compiled-build additions to tests/test_protocol_conformance.py and narrowly related test-only helpers, using CURATOR_CONFORMANCE_ROOT. Exercise real manifest parsing, install planning, build and cache behavior, rollback and repair, shim launch, argument and exit propagation, and rejection ordering in isolated temporary homes and projects. Implement the suite-defined test-only result sink and record contract without adding a user-facing csk command. Extend the existing rc.4 vector consumer rather than replacing it. Do not call or import Curator, copy shared vectors into the repository, weaken no-skip behavior, or change the curator-spec CI pin in this task.

## Acceptance Criteria
With CURATOR_CONFORMANCE_ROOT set, the Python consumer parametrizes every shared compiled-build case exactly once and fails on unknown, missing, duplicate, xfailed, or skipped case IDs. When the suite-defined result sink is supplied, it emits exactly one schema-valid JSON Lines record per case with the verified suite digest, normalized outcome, compiler boundary, persistent-mutation class, and exact launch argv, stdout, stderr, and exit status; it emits no implementation-owned expected value or release claim. The unmodified shared fixture proves cache miss, verified hit, corrupt or untrusted rebuild, compiler-free and mutation-free dry-run including audit-registry state, build-root context and runtime exclusion, failed-build rollback, recovery, currentness, repair, locked GC, two-project isolation, and explicit launch. Every shared negative case is rejected in the expected normalized class and at the required before-build or before-mutation boundary. Test homes, project roots, Go caches, and subprocess recording are isolated per case; no binary hash or local oracle is introduced. Focused external-suite tests, the full pytest suite, and strict type checking pass when the suite is supplied, while developer runs may skip only when CURATOR_CONFORMANCE_ROOT and the result sink are both absent.
