# Define shared executable compiled-build interoperability cases

## Description
Extend curator-spec with a manager-neutral executable interoperability layer that reuses the protocol-owned schema v6 Go fixture and normative build and lifecycle vectors. The shared suite is the only owner of inputs and expected outcomes, so Curator and csk remain independent consumers rather than copies of one another.

## Scope
Work in curator-spec after TASK-260720-1s1vr6 and TASK-260720-cw39jh. Extend the exact Go fixture path landed by TASK-260720-1s1vr6 rather than adding a second fixture. Own conformance/v1/vectors/compiled-build-interop.json, its generator and tests in tools/generate-vectors, conformance/v1/manifest.json inventory, and the suite-owned test-only consumer-result transport and JSON record contract. Define portable install, cache, dry-run, lifecycle, and launch cases by referencing the authoritative build-driver and manager-lifecycle vectors wherever possible. Do not duplicate schema or lifecycle payloads, compare platform-dependent binary bytes, prescribe manager-home paths, import implementation packages, create a user-facing manager API, or update release pins.

## Acceptance Criteria
The shared case file has stable case IDs and records the fixture path, operation, expected normalized outcome, expected persistent-mutation class, expected compiler-process class, and launch stdout, stderr, argument, and exit behavior where applicable. The suite-owned test contract names one caller-supplied result sink, a deterministic JSON Lines encoding, and required case_id, implementation, suite_sha256, outcome_class, compiler_process_class, persistent_mutation_class, launch_argv, launch_stdout, launch_stderr, and launch_exit_code fields without encoding release claims. The complete schema v6 fixture contains one build_roots entry, one go-v1 main command, a vendored dependency, a transitive embedded input, unrelated prompt context, and deterministic argument forwarding plus a nonzero-exit mode. Stable cases cover cache miss, verified hit, corrupt or untrusted rebuild, compiler-free dry-run, build-root context and runtime exclusion, explicit launch, failed-build rollback, interrupted recovery, currentness, repair, locked GC, and two-project isolation by reference rather than copied vector payloads. Every build-driver and compiled manager-lifecycle rejection case is included or referenced by stable ID with the same normalized class and before-build or before-mutation boundary. The generator imports no manager code, regeneration is byte-stable, legacy fixture values remain unchanged, and make validate plus make regenerate-check pass.
