# Run both managers through one black-box interoperability gate

## Description
Add a curator-spec-owned runner that invokes the two independent conformance entrypoints against the same immutable suite root and compares their normalized case results without importing either implementation.

## Scope
Work in curator-spec after TASK-260720-1673lr and TASK-260720-31zeo2. Own tools/run_compiled_build_interop.py, tools/test_run_compiled_build_interop.py, and the corresponding execution section in conformance/README.md. Consume, validate, and preserve the suite-owned result transport and record contract delivered by TASK-260720-2g7avf rather than redefining it. Accept explicit Curator and csk checkout or executable paths plus the suite root; create separate temporary manager homes, projects, caches, and fixture copies; collect one machine-readable result record per case. The suite remains the oracle. Do not embed manager refs, release pins, copied expected values, implementation-specific cache layouts, broad normalization rules, or cross-manager code imports.

## Acceptance Criteria
The runner validates the suite manifest and consumer-result contract before execution, invokes each manager consumer with identical suite bytes and separate result sinks, and rejects schema-invalid, missing, extra, duplicate, skipped, xfailed, timed-out, or crashed cases. Its normalization removes only suite-declared transport differences such as temporary absolute paths and platform executable suffixes; acceptance or rejection class, compiler boundary, mutation class, recovery or repair result, launch stdout and stderr, forwarded arguments, and exit status remain comparable. The two managers run in disjoint state roots and never consume one another cache or artifacts. A JSON report identifies the suite digest, caller-supplied implementation identities, per-case outcomes, and parity verdict without claiming release conformance. Unit tests inject divergent, malformed, missing, duplicate, skipped, timeout, crash, wrong-suite-digest, and unknown-field result streams and prove the runner fails closed. The documented local command succeeds against qualified checkouts and curator-spec validation remains green.
