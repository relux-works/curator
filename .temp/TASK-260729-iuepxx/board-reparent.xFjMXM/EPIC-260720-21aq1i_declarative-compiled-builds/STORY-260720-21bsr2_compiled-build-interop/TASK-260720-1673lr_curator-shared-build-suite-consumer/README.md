# Consume the shared compiled-build suite in Curator

## Description
Add an independent Go consumer for every shared compiled-build interoperability case. The consumer must exercise Curator behavior against the external suite root and derive no expected values from csk or from implementation-local fixtures.

## Scope
Work in the Curator repository after the Curator Go build-driver conformance handoff and TASK-260720-2g7avf. Own internal/interop/compiled_build_test.go and narrowly related test-only helpers, using CURATOR_CONFORMANCE_ROOT. Exercise real manifest parsing, install planning, build and cache behavior, rollback and repair, shim launch, argument and exit propagation, and rejection ordering in isolated temporary homes and projects. Implement the suite-defined test-only result sink and record contract without adding a user-facing Curator command. Extend the existing rc.4 vector consumer rather than replacing it. Do not call or import csk, copy shared vectors into the repository, weaken no-skip behavior, or change the curator-spec CI pin in this task.

## Acceptance Criteria
With CURATOR_CONFORMANCE_ROOT set, the Go consumer enumerates every shared compiled-build case exactly once and fails on unknown, missing, duplicate, or skipped case IDs. When the suite-defined result sink is supplied, it emits exactly one schema-valid JSON Lines record per case with the verified suite digest, normalized outcome, compiler boundary, persistent-mutation class, and exact launch argv, stdout, stderr, and exit status; it emits no implementation-owned expected value or release claim. The unmodified shared fixture proves cache miss, verified hit, corrupt or untrusted rebuild, compiler-free and mutation-free dry-run, build-root context and runtime exclusion, failed-build rollback, recovery, currentness, repair, locked GC, two-project isolation, and explicit launch. Every shared negative case is rejected in the expected normalized class and at the required before-build or before-mutation boundary. Test homes, project roots, Go caches, and subprocess recording are isolated per case; no binary hash or local oracle is introduced. Focused external-suite tests and go test ./... pass when the suite is supplied, while developer runs may skip only when CURATOR_CONFORMANCE_ROOT and the result sink are both absent.
