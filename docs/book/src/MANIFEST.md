# Рисунки книги: манифест

Каждый рисунок книги рисуется генератором `docs/book/kit/render.py` из исходника TOML в этом каталоге по правилам рисунков книги Swarma (`editorial/diagram-style.ru.md` в репозитории `swarma-docs`); рендер ложится в `docs/book/diagrams/<имя>.svg`. Генератор, тема и метрики шрифтов лежат в `docs/book/kit/` байт в байт как в исходном репозитории; их происхождение и хэши записаны в `docs/book/kit/README.md`. Из корня репозитория:

```
python3 docs/book/kit/render.py docs/book/src/<имя>.toml docs/book/diagrams/<имя>.svg --report --require-fit <поле>
```

Поле `tall` (167 × 168 мм) получает рисунок, чья ссылка в главе несёт класс `{.tall}`; остальные стоят в обычном поле 167 × 98 мм. Раскладка `graph` требует Graphviz 14.0.4, генератор при другой версии отказывает.

Проверку `docs/book/check-figures.sh` запускает сама сборка `docs/book/build.sh`. Структурный проход идёт всегда и Graphviz не требует: у каждой картинки из глав есть файл в `diagrams/`, исходник и строка здесь, все ссылки на рисунок несут один класс поля и столбец "Поле" его называет, у каждой копии хэш совпадает с записанным, в `diagrams/` нет картинок без исходника и у каждого исходника есть рендер. Проход рендера требует Python 3.11+ и Graphviz 14.0.4 и без них валит сборку: каждый SVG совпадает со свежим рендером своего исходника и проходит `--require-fit` для своего поля. Черновая сборка с `BOOK_SKIP_FIGURE_RENDER=1` пропускает только проход рендера и предупреждает об этом. Картинка, которую WeasyPrint не смог загрузить, тоже валит сборку. Отдельно: `bash docs/book/check-figures.sh` (оба прохода), `--structural` или `--render`.

**Происхождение.** "книга": исходник ведёт эта книга. "копия": байт в байт копия исходника из другого репозитория на записанной ревизии; править её здесь нельзя, в столбце "SHA-256 копии" стоит её хэш. Сейчас копий нет.
