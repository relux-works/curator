# План книги «Curator: окружение агента»

Книга идёт от различения данных и управляющего контекста к установке,
проверке и запуску. Каждая глава читается самостоятельно после главы
«Слои контекста». Внешние зависимости вводятся по роли, без истории разработки.

| Глава | Вопрос читателя | Содержание | Наличие текста |
| --- | --- | --- | --- |
| Для кого эта книга | Что здесь объясняют? | Термины, границы, статусы и маршрут чтения | Полная глава |
| Зачем управлять окружением | Почему одного файла инструкций мало? | Скрытые входы, воспроизводимость, данные и полномочия | Полная глава |
| Слои контекста | Что именно получает агент и в каком порядке? | Context package, profile root, project context, native discovery, additive composition | Полная глава |
| Профили и воспроизводимые источники | Как намерение становится проверяемым набором? | Profile manifest, Skillfile, sources, lock, overlays, audit | Полная глава |
| Managed home | Кто владеет файлами и что восстанавливается? | Layout, adapters, seeds, projections, drift, repair, recovery, credentials | Полная глава |
| Project context и Werkstatt | Как принять инструкции проекта, не доверяя всему checkout? | Registration, candidates, per-item approval, composition, scope, leases, worktree | Полная глава |
| Environments и запуск | Кто собирает процесс и кто им владеет? | Fragment, общий construction site, delegated, exact plan, detached, resume | Следующая редакция; обзор маршрута уже дан |
| MCP и инструменты проекта | Как сервер становится разрешённым инструментом? | Skillfile declarations, packages, inline approval, normalized digests, native writers | Следующая редакция; граница одобрения уже объяснена |
| Безопасность и permissions | Где заканчивается управление контекстом? | Ceilings, grants, source exclusion, credentials, audit и sandbox | Следующая редакция |
| Практические сценарии | Как пройти весь путь? | Новый профиль, новый проект, update, revoke, recovery, перенос рабочего места | Следующая редакция |
| Справочник CLI | Какая команда меняет какое состояние? | Команды, диагностики, read-only и mutation paths | Следующая редакция |
| Словарь и карта готовности | Что означает термин и что уже доступно? | Краткие определения, поддерживаемые границы и открытые вопросы | Следующая редакция |

Пять обязательных рисунков имеют самостоятельные исходники: порядок слоёв,
profile → lock → managed home, candidate → approval → composition,
Werkstatt и маршрут запуска. Добавление глав не требует объединять рисунки
в одну схему.
