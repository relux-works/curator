# Где мы

Книга описывает Curator в завершённом виде, а реализован он не целиком. Часть механизмов работает сегодня, часть принята владельцами или описана в спецификации модуля, часть остаётся открытым вопросом. Каждая строка этой главы относится к названной части и её границе. Состояние указано на 27 октября 2026 года по основным веткам Curator и спецификации curator-spec и по лаунчеру `curator-run` 0.5.0.

## Словарь статусов

| Статус | Основание |
| --- | --- |
| работает сегодня | Есть в коде и используется в названных условиях. |
| решено | Владельцы приняли решение; это не свидетельство работающего кода. |
| спецификация | Описано в спецификации модуля; это не свидетельство реализации. |
| предложено | Архитектурное предложение ожидает решения. |
| открыто | Вопрос не решён. |

Столбец "Статус" несёт ровно один статус словаря. Если у части несколько состояний, она разбита на строки, по строке на состояние. Скобки после "работает сегодня" называют выпуск лаунчера `curator-run`, с которого часть работает. Если код части входит в основную ветку Curator только как внутренняя библиотека менеджера, без команды CLI и без запуска, строка несёт статус по спецификации модуля, а состояние кода названо в столбце "Что это".

## Профили и источники

| Часть | Что это | Статус |
| --- | --- | --- |
| Контекстный пакет | Манифест `agent-context.json` схем 1 и 2 называет модули из каталога `context/` с их агентскими средами и классом и требования `requires.contexts`, `requires.skills`, `requires.mcp`. Curator проверяет путь и байты каждого модуля: обычный файл, UTF-8, LF и ровно один завершающий перевод строки. | работает сегодня |
| Профиль и lock-файл | `curator profile install` ставит профиль из git или каталога, разрешает замыкание требований в формах `range`, `tag` или `revision` и пишет lock с пинами членов. Хэш lock служит пином профиля, несовместимые требования к одному имени останавливают разрешение. | работает сегодня |
| Каталог скилла в требовании профиля | Поле `directory` в требовании скилла схемы 2 входит в идентичность скилла, и lock схемы 4 связывает выбранный каталог. | работает сегодня |
| Кандидат при установке и обновлении | Новый lock проверяется как кандидат: отказ проверки оставляет прежний lock, предыдущий хранится в `lock.prev.json`. Изменения идут под блокировкой менеджера и через журнал транзакций. | работает сегодня |
| Частичная активация при конфликте поверхностей | Новый lock может остаться опубликованным, а конфликтующие поверхности сохраняют прежнее состояние. | спецификация |
| Корневой контекст профиля | Документ корневых инструкций вычисляется из lock и политики старшинства и несёт заголовок генерации с членами, пинами и хэшем lock; ручная правка обнаруживается как дрейф. Пакет без секции `context` файла не пишет, профиль без применимых модулей получает документ из одного заголовка. | работает сегодня |
| Политика старшинства | Направление веса `higher-weight` или `lower-weight` и порядок победителя `winner-last` или `winner-first`, по умолчанию `higher-weight` и `winner-last`. Lock схемы 4 хранит выбранную политику. | работает сегодня |
| Классы модулей `root` и `system` | Модули `system` идут отдельным каналом. Транзитивный модуль `system` отбрасывается с предупреждением `context_system_module_dropped` или останавливает разрешение с `context_system_module_transitive`, исключения задаёт `system_module_waivers`. | работает сегодня |
| Формы `monolithic` и `referenced` | Claude Code и OpenCode принимают обе формы корневого контекста, Codex, Muse и Pi только `monolithic`. | работает сегодня |
| Skillfile проекта | Skillfile схемы 2 с именованными источниками `path` и git, коллекциями, командами `resolve`, `install`, `status`, `refresh` и диагностикой `source_lock_stale`. У Skillfile свои схема, lock и область действия; пропавший снимок восстанавливается по закреплённой ревизии при совпадении идентичности и `content_sha256`. | работает сегодня |
| Оверлеи профиля | Машинная конфигурация `overlays.<профиль>` добавляет к профилю пакеты из git или локального каталога с весом; `curator profile compose add` записывает оверлей. | работает сегодня |
| Команды скиллов профиля | Профиль ставит команды своих скиллов тем же установщиком, аудитом и сборкой, что и обычные скиллы, шимы текущего профиля попадают в машинный каталог команд. Curator разбирает поля `mode` и `commands`, но установка профиля сборку команд не запускает. | решено |
| Корень команд на lock профиля | У каждого профиля свой каталог команд под хэшем lock; fragment передаёт его в `path_prepend`, лаунчер проверяет каталог и ставит его в начало `PATH`. `curator-run` 0.5.0 разбирает и проверяет `path_prepend`, но `PATH` не меняет. | решено |
| Преемник lock профиля для команд | Lock `context-lock-v5` с планом скиллов `profile-skill-plan-v1`: узлы, рёбра активации и выбор команд. Спецификация модуля несёт его как предложенное распределение, не принятое и не выпущенное. | предложено |
| Схемы для команд профиля | Грамматика корня команд, носитель снимка, аренда и сборка мусора, поиск команд в Windows, старшинство проекта. | открыто |

## Управляемый дом

| Часть | Что это | Статус |
| --- | --- | --- |
| Дом профиля | Дом на пару профиль × агентская среда в `environments/<профиль>/<среда>/`; чекаут в ключ не входит. Каталоги создаются с правами `0700`, файлы менеджера с `0600`, восстановление сужает права старых домов. | работает сегодня |
| Отображения агентских сред | Для `claude_code`, `codex_cli`, `muse`, `pi` и `opencode` реестр задаёт переменные дома и пути корневых инструкций. Отображение не подтверждает каждый сценарий запуска у внешнего потребителя. | работает сегодня |
| Маркер и классы файлов | Маркер `.agent-environment.json` перечисляет сгенерированные поверхности, начальные файлы, записи учётных данных и нативное состояние; `--repair` трогает только управляемое. | работает сегодня |
| Начальные файлы | Curator читает нативный исходник начального файла только при создании дома, восстановление его не перечитывает. `.claude.json` создаётся с записью доверия каталогу запуска; после первого запуска файлом владеет харнес, и восстановление сливает только флаги этой записи. | работает сегодня |
| Начальный файл Codex ревизии C | Новый дом Codex получает `config.toml` без `mcp_servers` и `projects` и предупреждение `mcp_native_servers_not_inherited`. Старые дома сохраняют байты: дом ревизии A сообщает `mcp_native_servers_ungoverned` и `mcp_seed_unstripped`, переписи ревизии нет. | работает сегодня |
| Проекция скиллов | Контекст скилла публикуется в `skill-context/` и связывается с домом управляемыми и нативными ссылками для Claude Code, Codex и Pi; команды скиллов идут в отдельные хранилища исполнения. Восстановление обменивает ссылки атомарно на macOS и Linux. | работает сегодня |
| Проверка и восстановление дома | `curator env resolve` сообщает `environment_home_stale`, `--repair` восстанавливает поверхности и переносит старый lock, `--dry-run` ничего не пишет, `--preserve-lock` отказывает до записи при любом изменении хэша lock. `curator env status --check --json` проверяет дом без записи. | работает сегодня |
| Журнал транзакций и блокировка менеджера | Изменения идут через промежуточный каталог, резервные копии, переименование и откат. Блокировка ждёт 30 секунд и отказывает `environment_lock_unavailable`. | работает сегодня |
| Перехват чужого файла | `--takeover` берёт под управление файл, который Curator не создавал, и сохраняет резервную копию; `curator env unmanage --restore-backups` возвращает копии. | работает сегодня |
| Режимы входа `shared` и `isolated` | Выбор на пару профиль × среда с ограничениями по адаптерам и платформам; секреты в lock не попадают. Изоляции учётной записи у провайдера режимы не дают. | работает сегодня |
| Миграция учётных данных | `curator env migrate` с `--inspect`, `--plan` и `--apply --expect <хэш плана>`. Дрейф описи и конфликты отказывают, байты учётных данных команда не трогает. | работает сегодня |
| Селектор `credential_store` | Значения `native`, `file` и `keychain` хранятся на пару профиль × среда; Muse с `native` или `file` получает файловое хранилище. | работает сегодня |
| Отказ явных `file` и `keychain` для остальных сред | Codex с `file` отказывает `codex_settings_unsupported`, прочие сочетания отказывают `environment_credential_store_unsupported`. Применение этих хранилищ отключено, и явный выбор к `native` не откатывается. | работает сегодня |
| Снимок дома `curator env materialize` | Проверенный снимок без учётных данных в отсутствующий каталог вызывающего, публикация переименованием без замены, сверка дайджестов при подключении и возобновлении (контракт снимков управляемого дома, CIP-0014). В Curator есть библиотеки допуска каталога назначения, публикации, проверки и захвата содержимого; команды `env materialize`, интеграции с запуском и восстановления после сбоя нет. | спецификация |
