# Project home and lease manager

`internal/projectlease` implements the manager side of CIP-0002 leaf 3 and
`protocol/project-context.md` sections 2, 5 and 6. Existing profile-only managed
homes keep their paths and publication behavior. Project composition and tracked
session integrations supply protected authority through the interfaces below;
this leaf exposes no external lease CLI and accepts no repository records.

## Authority contract

```go
type Authority interface {
    Resolve(context.Context, managerlock.Held, string, string) (Composition, error)
    Authorize(context.Context, managerlock.Held, Composition, string) error
}
type Sessions interface {
    Observe(context.Context, string, int64) (Evidence, error)
}
```

`Resolve` receives an opaque `composition:ID` and its 64-character lowercase
hex CCJ-1 digest. It must resolve only issuing-manager immutable records and
verify the complete composition, registration/home binding and materialization
receipt before returning `Composition`. The projection contains `Ref`, `SHA256`,
`CheckoutID`, `Profile`, `Environment`, `HomeRef`, `ConcurrentState`, `BuildKeys`,
`RuntimeEntries`, and `Generated`. `Generated` is a complete map of relative
paths to `Surface{SHA256 string, Size int64, Mode uint32}`. Modes are the numeric
values of `0600` and `0700`; the wire receipt keeps its owning grammar.
`ConcurrentState` comes from the qualified adapter, never a repository option.
`BuildKeys` and `RuntimeEntries` name the existing build and runtime GC keys.
Empty inventories are explicit empty maps/slices.

`Authorize` checks current admission, grants and revocation for that composition
and principal. Known revocation returns `projectlease.ErrRevoked`; unreadable
or unavailable authority returns another error. Neither method may fetch,
repair or accept caller-authored authority. Missing interfaces refuse admission.
These callbacks receive an explicit borrowed `managerlock.Held` witness while
its owning manager-home lock remains held. Before every protected read, the
resolver calls `held.Validate(home)` to verify a live, unreplaced lock for its
exact canonical manager home. Zero, stale and another-home witnesses refuse.
Only lock acquisition mints a witness; `(*HomeLock).Held()` borrows it without
release authority. Retaining a witness does not extend lock lifetime, and a
later acquisition does not revive an old witness. Callbacks never reacquire
the lock. The caller acquires any project lock before entering this API.

`Observe` receives the reserved session reference and positive session
generation. Its evidence must bind those exact values, the owner principal,
and a nonempty process/runner incarnation before transfer. `Running` describes
the tracked session, including surviving descendants. `NoChildStarted` is an
authoritative reservation/pre-start-abort fact. Termination needs all of
`Terminated`, `DescendantsTerminated` and `OwnershipReconciled`, with the
recorded process incarnation. PID, launcher exit and elapsed time supply none
of this proof. The session authority must persist transfer/reservation state
and must establish the runner before any provider or child can start.

## Operations

Construct `New(home, authority, sessions)` with the manager's protected root.
The constructor does not provision state. Each mutation acquires the existing
manager-home lock and uses the shared recoverable transaction engine.

| Operation | Inputs and successful output | Refusals and ordering |
| --- | --- | --- |
| `Acquire` | `Request{LeaseID, ContextRef, ContextSHA256, OwnerRef, SessionRef, Generation}`; returns immutable `Binding` and durably stores `prepared`. | Requires current authority and reserved no-child session; duplicate lease/session generation refuses. Another composition or an exclusive adapter returns `project_view_busy`. Referenced runtime/build entry directories must still exist under this same home lock before the lease commits; missing or unsafe entries return `ErrArtifactsUnavailable`. Reserve before publication or fragment emission. |
| `PublishPrepared` | Lease ID, complete generated file bytes, wait flag; transactionally publishes the protected receipt into the stable home. | Requires `prepared`; exact inventory/hash/size/mode checks; no native-file takeover. Identical verified already-published bytes may be shared without writing. Changed generated files refuse while active/unknown leases exist. |
| `Transfer` | Prepared lease ID; durably establishes `active` with the reserved runner incarnation. | Requires verified published files, current authority and a running reserved runner with no child started. Must succeed before provider start and before launching process exit. |
| `Update` | Composition ref/digest, owner, complete generated bytes, wait flag; idle repair/profile/skill/CLI sync reuses the home transactionally. | Every lease, including `prepared` and `unknown`, returns `project_view_busy` before file changes. Repairs changed, missing or mode-drifted inventoried regular files from the approved receipt; unsafe routes, replacement directories and unmanaged native collisions refuse. No alternate home is allocated. |
| `Reconcile` | Lease ID; persists the authoritative lifecycle observation. | Missing/mismatched session/process evidence becomes `unknown`. Only complete termination/descendant/ownership proof releases an active lease. A pre-start abort requires no-child and ownership proof. |
| `Recover` | Manager root; recovers pending transactions and marks all interrupted non-released leases `unknown`. | No PID/TTL-based release. Reconciliation is explicit. Unreadable ledger/binding evidence refuses and preserves roots. |
| `Resume` | Active reconciled lease ID; returns its original `Binding` after current authority, runner-incarnation and generated-file checks. | Unknown, released, revoked or drifted evidence refuses. It never selects the current generation or starts a replacement launch. |
| `PrepareResume` | Released reconciled original lease ID plus a new reserved `Request`; returns a new prepared binding to the original composition. | Caller retargeting refuses. Rechecks current authority; failure allocates no replacement lease. Complete `PublishPrepared`/`Transfer` again before starting the resumed provider. |
| `Status` | Context; returns ordered `Status` rows, including binding, state, busy, observed liveness and authority uncertainty/revocation. | Read-only existing-lock acquisition; never provisions, recovers, approves, fetches or rebaselines. Pending recovery reports unknown/busy. Unreadable state returns an error. |
| `ReferencesUnderLock` | Manager root and caller-held home-lock witness; returns home, composition, build and runtime roots. | Requires a live `Held.Validate(home)` acquisition witness for this exact manager home, including when no ledger exists. Assertion-only, foreign, released/reacquired and replaced lock witnesses refuse. Pending project-lease transaction intent returns `ErrPendingRecovery` before any pruning or sweep, including before the first ledger exists. Keep the owning lock open throughout collection. Unknown/unreadable references never become an empty mark set. Existing GC merges build/runtime roots before sweeping. |

Busy errors name owning sessions and advise waiting or ending them. With
`wait=true`, a busy update releases the lock between checks and honors context
cancellation; cancellation retains the busy diagnostic and original bytes.
No release action is associated with detach or the lifetime of a `Manager`.

## Storage and publication

Native homes remain stable at
`environments/project-views/<checkout-id>/<profile>/<environment>/`.
Adapter-owned native state stays there across idle composition updates. The
manager changes only the separately inventoried generated regular files.
Unrecorded native collisions always refuse. Shared publication, transfer and
resume require verified generated bytes/modes; live leases block idle repair.
After all leases release, `Update` uses the protected old inventory to identify
owned file names and restores the supplied approved receipt despite byte,
absence or mode drift. It refuses links, unsafe parents and directory
replacements rather than adopting unrecorded children. A repair fault restores
the actual drifted preimage together with the ledger. Empty
generated inventories still provision a private native home before transfer;
a missing or unsafe existing home refuses resume/shared publication without
recreating it beneath a lease. Directory creation follows the transaction
engine's existing parent-directory convention; generated bytes and publication
records remain journaled together.

Binding parsing rejects case-insensitive member aliases even in canonical JSON.
Bindings are exact closed `project-lease/1` CCJ-1 objects under
`state/project-leases/v1/bindings/`. A binding never changes when lifecycle
state changes. The private `ledger.json` beside them stores lifecycle state,
runner incarnation, generated inventories and conservative GC roots. Binding
bytes are checked against the ledger on every read; a missing ledger in an
existing project namespace is unknown evidence. There is no mutable `current`
composition reference. The issuer's composition records remain owned by the
composition integration.

Output paths reject traversal, links, portable case/normalization aliases and
file/ancestor collisions. Inventories observe the normative path, size and mode
limits. Native mutable files are never included in a generated receipt.
Publication uses one transaction for generated files and the ledger; faults
roll back or retain explicit recovery intent. Acquisition, publication and GC
serialize on the same exact-home lock, so a lease cannot race an idle update
or a collector. After durable Prepare, the transaction commit check revalidates
the current acquisition witness and referenced entries before forward writes.
The same check runs during restart recovery; missing artifacts cause rollback,
including restoration of the prior ledger and removal of a partially installed
new binding. The desired ledger is read only from a staged/live candidate that
matches the journal digest, never from an older live ledger.

Manager, default install, profile mutation and CLI GC engines install
`transaction.WithCommitCheck(projectlease.TransactionCheck(home))`. Integrations
that construct another engine capable of recovering project-lease journals must
install this policy too. The generic engine retains its previous behavior for
other owners and for callers without a check. The policy receives the current
caller's borrowed lock and a journal snapshot; rollback does not consult it.

Immediately before preparing a lease, acquisition rechecks
referenced runtime and build entry directories in the existing GC namespaces.
This checks presence and route boundaries; complete payload/hash/receipt
validation remains the composition authority's responsibility.

The bounded ledger is at most 1 MiB. Released bindings and materialized views
remain conservative resumable roots; this leaf does not prune their history.
A full ledger refuses further allocation without discarding existing state.
A failed first admission may leave an uncommitted namespace and source staging
files after rollback. The existing missing-ledger rule retains that uncertain
namespace and refuses further collection; it never treats it as an empty mark
set or commits a binding that names absent artifacts.
Windows builds retain owner-only DACL checks and logical receipt modes; exact
Unix mode-bit checks apply on macOS/Linux. No Windows native project adapter
qualification is implied. Native exclusion, actual provider start, auth and
composition construction are separate integration/qualification leaves.

## Verification

Run `env -u GIT_DIR -u GIT_WORK_TREE go test ./internal/managerlock ./internal/projectlease ./internal/scopes`
and `env -u GIT_DIR -u GIT_WORK_TREE go test ./internal/transaction ./internal/envprofile ./internal/install ./cmd/curator`.
The fixtures cover independent projects, qualified shared sessions, exclusive
adapters, busy refuse/wait/cancel, login preservation, receipt/mode/path checks,
rollback/recovery, launcher subprocess exit, descendants, unknown liveness,
process-incarnation reuse, resume and revocation. Real runtime/build-cache GC
controls retain referenced artifacts and remove an unreferenced neighbor.
The paused-acquisition/foreign-lock collector regression checks physical
artifact retention before acquisition continues. Idle repair cases cover
changed/missing/mode drift, live refusal, native directory refusal and fault
rollback. Actual admission subprocess exits at Prepare and after a first install
exercise pending-intent GC refusal, intact recovery and missing runtime/build
rollback. Default install/profile/GC recovery policies have separate controls,
as do exact binding members and the generic commit check. Each new gate has a
bounded overlay control.
Bounded source overlays require intended assertion failures for PID-only,
launcher-return release, TTL-only collection and the affected gates; crashes
and unrelated failures never count. Keep local logs/caches in `.temp/` and run
the complete default suite in a clean normal checkout at the delivery head.
