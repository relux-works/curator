# Home lease qualification map

This map indexes the first 68 semantic pairs of the [accepted corpus](https://github.com/relux-works/curator-spec/blob/264244b321c7a2272450fc29bd9952f988d746d7/conformance/home-leases-v1/cases.json), whose pinned revision carries 110 pairs after the HL07 observer additions; the added observer rows are mapped in the production observer boundary section below by their stable case suffixes. This map is **not a claim of complete runtime pairs**. Each row names actual tests and the remaining limit. `store`/`guard` identify the local boundary tested; store lifecycle positives use explicitly synthetic independent authority/observation, while the production observer boundary below is exercised through its real transport shape, a substituted kernel source and one real owned child per native platform. `partial` and `consumer gap` remain acceptance gaps. No skipped consumer test or made-up launcher is counted as a pass.

Tests are in this package, `state/`, `observation/`, `../envprofile/homelease*_test.go`, and `../../cmd/curator/env_homelease_test.go`. Refusal preimages are checked before positive controls. The producer observation vectors are an additional transport oracle, not a substitute for semantic pairs.

## Production observer boundary

The CLI wires `SessionManagerObserver` to `curator-run session-manager observe <manager-id> --session <SES-handle> --json --schema v2 --expect-registered-at <prepared registration> --expect-generation <requested generation>`, adding `--expect-executable` only when a frozen launcher binding supplies one. The v1 schemas and producer vector file remain copied byte-for-byte under `observation/` for the v1 wire contract; the v2 reply is validated closed at its envelope and at every authority-bearing member (capability, readable/state placement, generation, the process tuple and the termination variants). Transport is capped at 64 KiB, requires strict JSON, discards stderr and has a 25-second total deadline (producer describe/status each allow 10 seconds).

Bind then re-reads the kernel incarnation itself: field 22 of `/proc/<pid>/stat` (counted after the last `)` of comm) with the `AT_CLKTCK` rate `sysconf(_SC_CLK_TCK)` reports, the real uid from `/proc/<pid>/status` through one `/proc/<pid>` directory fd with stat and boot id read before and after, and on macOS one `proc_pidinfo` `PROC_PIDTBSDINFO` call plus lowercased `kern.bootsessionuuid`. Only byte equality across requested holder, v2 tuple and kernel reading binds; unequal fields refuse `process_incarnation_mismatch`, while vanished, unreadable, unsupported-variant or missing evidence refuses `authority_unavailable`, always preserving the blocking lease. An identical committed bind retry re-verifies. The adapter never copies caller process/request/Werkstatt fields or labels into trusted evidence. Release gains no authority from a matching tuple or a termination claim: without qualified authoritative reconciliation it keeps `environment_lease_release_unconfirmed/session_state_unknown`. Platforms without a native observer build and vet but refuse every production bind.

`TestProductionBindObserverRows` pairs the matching-tuple bind with the refusal rows (pid reuse within and across boots, wrong real uid, manager/kernel and holder/observation disagreements, the remaining start-time member, in-pass incarnation change, unavailable observation, missing process, vanished pid, unreadable field); `TestLinuxKernelReadsOwnChild`/`TestDarwinKernelReadsOwnChild` read a real owned child per platform; `TestObserverPlants` kills the skipped-start-time, trust-the-manager, unreverified-retry and dropped-uid-ceiling plants. `TestProductionObserverRetainsUnprovenLease` exercises the real bounded process transport with synthetic executables and the real store. `observation.TestPublishedObservationVectors`, `TestObservationTransportAndClosedProofs` and the `ParseV2` tests cover the exact closed wire contracts. Real launcher/proving-manager docking and macOS execution remain later qualification; the macOS observer is build- and vet-checked here.

## Writer and consumer audit

All 18 writer rows have code admission hooks, either at their held operation or common transaction publisher/recovery. Rows 25–42 above distinguish that code audit from complete variant qualification. The central gates are `homeLeaseGuard`, `homeLeaseGuardPlan`, `homeLeaseGuardUndo`, `state.GuardMutation` and the transaction engine's complete target inventory. They check forward and rollback before replay, retaining the continuous real managerlock witness. Broad legacy whole-manager paths currently refuse conservatively; they are not qualified as fully disjoint writers.

New hooks in this continuation: the one-line production observer argument in `cmd/curator/env.go`; `native_mcp.go` runs the existing ownership preflight before operation admission, then revalidates captured inputs under the held operation rather than replanning against its own postimage. The latter was exposed by the W11 positive control. The race fixture sends native paths in its existing closed stdin payload and does not inherit per-test provider overrides across the helper boundary. No containment commit is rewritten.

GC's runtime and protected build-cache sweeps pass through the shared lock. Fixture publications exercise the existing cache APIs, prepared/unknown home roots, durable project roots, explicit home break and full pending-acquire refusal; the artifact bytes, inputs, portable receipts and independent authority are synthetic. Reconciliation alone does not discard durable project composition roots. The production profile materializer currently supplies empty build/runtime reference lists. Production profile compiled-closure activation and qualification remain separate work described in `docs/design/profile-skill-runtime.md`; these fixture roots do not qualify that bridge.

HL21–HL24 remain consumer requirements. Launcher main inspected here has no `lease_requested` integration. Curator cannot qualify durable op.json ordering, zero/exactly-one manager calls, immediate bind, abandon/bypass handling or lane/Werkstatt admission by simulating them inside its store tests. No live manager/provider qualification or activation was performed.
