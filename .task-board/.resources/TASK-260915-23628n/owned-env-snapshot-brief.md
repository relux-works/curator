# Brief — expose the owned-environment snapshot of an admitted plan (skill-agents-management)

Problem (from TASK-260908-1o7i8y_results.md on the curator board): `vendorplugin.BuildLaunch(ctx, registry, SpawnRequest, mode)` returns only `agentic.Plan`; the effective `LaunchRequest` it prepares (vendor translation, Runtime/Vendor assignment, preparation, alias projection) is private and never returned. The launcher SPEC §4.5 requires the owned environment literals from `System.ChildEnv(nil, req)` for the SAME effective request that built the admitted plan, and forbids diffing or a second BuildPlan. So the launcher cannot compose §4.5 without an upstream API.

Deliver (option 1 of the analysis):
1. At the admitted planning boundary inside BuildLaunch/BuildPlan, compute the owned environment snapshot `system.ChildEnv(nil, effectiveRequest)` (nil parent → owned literals only) and expose it with the plan. Preferred shape: a new exported field on `agentic.Plan` (e.g. `OwnedEnv []string`, sorted, deterministic, documented as "owned environment literals of the admitted request; consumers must not diff against a parent") populated by BuildPlan for every mode where ChildEnv is called; if adding a field to Plan is unacceptable for existing golden/JSON contracts, add `BuildLaunchResult{Plan, OwnedEnv}` via a new function `BuildLaunchWithEnvironment` and keep `BuildLaunch` byte-compatible. Record the choice and why in the results resource.
2. No behaviour change to existing plans: every existing golden/test stays green unchanged; new tests prove the snapshot equals what ChildEnv returns for the prepared request for claude, codex and pi-native systems (LaunchModeInteractive and the existing modes), and a narrowing mutant (snapshot taken before preparation/alias projection) is killed.
3. Document the field in the package docs and CHANGELOG (Unreleased → next patch version v0.5.13). Do NOT create the tag: the orchestrator cuts the signed tag on the reviewed head after landing.
Work in the managed Story worktree of skill-agents-management; handoff with `task-board handoff <TASK> --role developer`. Validation suite (go build/test) runs once via the runtime at handoff.
