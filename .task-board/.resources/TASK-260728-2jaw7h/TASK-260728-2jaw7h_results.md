### Boundary probe

The section 4.2.1.2 probe is landed at `tools/toolchain-boundary-probe`, builds
and vets inside the module, and has `make boundary-probe` and
`make boundary-probe-controls` targets. It is not part of `make validate`,
because it needs a real Go toolchain of each family in the manager's
`compatibility` set.

What `make validate` does enforce without a toolchain is agreement:
`check_probe_agreement` parses the probe's own `goCases` and `tcCases` tables
out of its source — 29 cases, 16 `go` and 13 `toolchain` — and holds every
fixture row the table marks `probe_measured` to the probe's class and
disposition, in both directions. A fixture that drifts from the probe is caught
on any runner. The direction is the reference's: the probe is authoritative and
the fixture is held to it.

## Two places where landing the contract completed it

Both are recorded in the reference document's header and are the changes a
reviewer should look at hardest.

1. **`source_ref.surface` gains `registry`.** Section 5.1 fixes the token set to
   `manifest`, `descriptor`, `source_metadata`, and section 2.3 makes the
   registry baseline a contributing source of the intersection. A
   `requirement_unsatisfiable` conflict payload names every source achieving the
   failing bound, and the most common unsatisfiable case is a manifest range
   below the baseline — where the bound that fails is the baseline's. Without a
   fourth token that payload cannot name it. Inventory case 29 and payload case
   66 both exercise it.
2. **A value classifier's absence class is marked as matching absence.** Section
   3.1.1 requires `forbidden` classes before `compared` and `ignored` ones, and
   sections 4.2.2 and 4.2.3 both put the `absent` class at position 1 with the
   forbidden classes at 2 and 3. The rule is about values; the absence class
   classifies no byte string. A `matches` member of `absence` or `value` makes
   that explicit and keeps the precedence check exact instead of special-casing
   a class name.
