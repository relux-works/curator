TASK-261008-1j34ro (N8: audit --allow accepts a path in place of a content digest) — developer results

CHANGE
- internal/hashing/hashing.go: new hashing.ParseDigest. Validates a supported
  content identity (64 hex chars, either case, with an optional "sha256:"
  prefix) and returns the lowercase bare digest. Everything else (paths,
  traversal, wrong length, non-hex) is refused before any filesystem access.
- internal/audit/audit.go: PinAtVersion parses the digest first (refusal
  before MkdirAll/WriteFile), then resolves the trust dir through a new
  pinDir helper that verifies containment inside home/audit before writing
  any pin state. trustDir, the pin record shape, and the version switch are
  unchanged, so all previously valid pins behave identically.
- cmd/curator/main.go (cmdAudit): --allow/--reason are validated up front,
  including a ParseDigest refusal with exit 2, before loadConfig — so a
  malformed --allow value never reaches config, trust, or pin state.
  PinAtVersion re-validates at the library boundary.
- CHANGELOG.md: one operator-visible line under Unreleased/Fixed.
