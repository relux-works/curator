# Brief — BUG-260918-3u6qqq: install-rust-toolchain.sh must find rustup under CARGO_HOME/bin (rose-air lane)

Facts (verified on main run 35290929324, rerun 2026-09-18 02:25Z after the operator installed rustup on macbook-iv): the step "Install pinned Rust toolchain via rustup" fails with `rust-pin: rustup is not installed on this runner; install it once per docs/self-hosted-runner-setup.md`. Cause: .github/ci/install-rust-toolchain.sh runs `command -v rustup` BEFORE it computes cargo_home and prepends `$cargo_home/bin` to PATH. The self-hosted runner service is started by launchd with a minimal PATH and the lane shell is `bash --noprofile --norc`, so a per-user rustup in ~/.cargo/bin (installed with `--no-modify-path` as the docs say) is never on PATH. Hosted images pass only because they ship rustup on PATH. Fix the script, not the runner.

Required change (small, exact):
1. In install-rust-toolchain.sh compute `cargo_home="${CARGO_HOME:-$HOME/.cargo}"` first; `export PATH="$cargo_home/bin:$PATH"`; then resolve rustup with `command -v rustup` (which now sees $cargo_home/bin). Keep the fail-closed named message when rustup is absent in both places. Append `$cargo_home/bin` to GITHUB_PATH as today (keep the GITHUB_PATH-required check). Keep channel parsing, `rustup toolchain install "$channel" --profile minimal`, the post-install rustc/cargo checks and the diagnostics exactly as they are.
2. gate-selftest.sh section "install-rust-toolchain.sh: rustup installs the filed channel, shims lead PATH" (line ~942): add rows (a) rustup present ONLY under a fake CARGO_HOME/bin and NOT on PATH → script succeeds and the fake install invocation is recorded; (b) rustup absent from PATH and CARGO_HOME/bin → exit 1 with the docs-named message; keep the existing rows green. Use the existing fake-rustup harness there (no network).
3. docs/self-hosted-runner-setup.md: one short paragraph — the runner service does not read shell profiles (launchd PATH), so rustup is expected under ~/.cargo/bin of the runner user (or CARGO_HOME) and the lane locates it itself; the installer's `--no-modify-path` form is fine. Do not tell the operator to edit PATH.
