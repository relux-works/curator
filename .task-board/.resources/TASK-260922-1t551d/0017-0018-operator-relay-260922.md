# Relay для сессии curator-spec/launcher по 0017/0018

Дата: 2026-09-22. Текст для передачи другому оркестратору как есть.

Ответ: принимать 0017 и 0018 как предложено, все выборы «самый строгий из работающих». Headless-набор оставить минимальным: TTY как главный признак закрывает Jenkins/Azure по факту, расширение списка CI-переменных сделать отдельной ревизией.

Три дополнения, все с evidence на живой машине:

1. 0017, Pi root. На Mac оператора managed pi home ссылается `~/.curator/environments/default/pi/auth.json → ~/.pi/auth.json`, а этого файла не существует; реальный credential лежит в `~/.pi/agent/auth.json`. То есть passthrough для pi сейчас dangling, и `env status` не показывает его как detached. O2 с исправленным корнем `~/.pi/agent` и F-C1 (ремонт credential-ссылок) нужны не гипотетически; F-C3 должен покрыть именно этот случай (link на несуществующий native файл).

2. 0017, Codex isolated. На машинах оператора ключ `cli_auth_credentials_store` в `config.toml` отсутствует, то есть default `file`, значит `isolated` для codex под предложенным правилом доступен. Наш дизайн профилей опирается на platform default и на 0017 сверх этого не завязан.

3. 0018, кто спеллит флаг. Launcher SPEC §1 и Decision 0013 D5 держат инвариант «launcher никогда не спеллит флаг провайдера, argv это дело system plugin». Маппинг `yolo → --dangerously-skip-permissions | --dangerously-bypass-approvals-and-sandbox` должен жить в agents-management как член `LaunchRequest` для `LaunchModeInteractive` с interactive goldens (positive и negative), а launcher только передаёт выбранный режим. В follow-up листе есть F-L1 (launcher) и F-A1 (ax), но нет пункта для agents-management; его нужно добавить, иначе 0018 либо нарушит 0013, либо продублирует argv-грамматику, которую `argvguard` модуля запрещает спеллить в двух местах.

Со стороны task-board 0017/0018 ничего не блокируют: tracked children спеллят bypass в exec-плагинах модуля сами; 0018 нужен только `curator run` и позже tracked-сессиям через ax.
