### Supported authoring and onboarding shape (conditional, not an instruction to migrate now)

Use a dedicated package directory. Do not make the unversioned product folder a repository or snapshot all its nested repositories as a profile. A minimal **illustrative** profile, not the approved op2-product manifest, is:

```json
{"schema_version":1,"name":"op2-product","version":"1.0.0",
 "context":{"modules":[{"path":"root.md"}]}}
```

Put the chosen root text in `context/root.md`. Convert only authoritative, reviewed AGENTS/CLAUDE material into explicit modules. Publish by versioning this separate package in Alexis's own Git repository, matching manifest `version: "1.0.0"` to tag `v1.0.0`, then install from that URL with `--tag v1.0.0 --as op2-product`. For local iteration, `profile install /absolute/path/to/package --as op2-product` takes an immutable snapshot; edits require reinstall. No `profile publish` command is needed: publishing is the package's ordinary Git/tag flow. Profile requirements use Git sources; authored local skills use project schema-2 path sources after G2 is fixed. MCP declarations use Git identities, not inline path packages.

After the bundle, approved package and R4/R9 checks are available, the operator-facing sequence is:

```sh
curator bootstrap --if-missing --non-interactive \
  --skills-root "$HOME/skills" --default-agents claude_code,codex_cli
curator project add op2-product "$HOME/src/op2-product"
curator profile install <Alexis-approved-profile-url> --tag <profile-tag> --as op2-product
curator env resolve claude_code --profile op2-product --repair --format json
curator env resolve codex_cli --profile op2-product --repair --format json
curator run claude --profile op2-product --permissions native
```

The angle-bracket operands are unresolved data, not runnable values. Commands above are a proposed guide sequence; P1 exercised their core primitives, not this exact live-machine walkthrough or the Git publish path. `--permissions native` adds no launcher permission override; it does not attest native file precedence or prompting. Inside the managed Claude session, authenticate as Alexis; for Codex shared-file mode, log in natively as Alexis with `codex login`, then the managed home links his own `~/.codex/auth.json`. Native keyring mode uses that operator's ambient keyring. Do not copy credentials between people or include them in context packages. Non-git Codex `exec` may need its native `--skip-git-repo-check` argument, as the Curator first-run notice documents; that was not exercised with real Codex here.
