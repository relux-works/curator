## F1 (rev5, high) — resolved

Rev5 finding: the external arm's execution receipt bound the compiler go-v1 view digest instead of the exact receipt-3 wrapper digest (skillfile-sources.md §4 lines 289-295, read from curator-spec main 5146c7b: "bind the exact receipt-3 build input digest in `build_input_sha256` … An implementation unable to bind that input MUST reject execution; it MUST NOT downgrade or claim compatibility based on a context-only hash").

How rev6 resolves it (read in full, not from the results file):
- `buildrepo.RunPipeline` (pipeline.go:322-327) sets `CompileRequest.ExpectedDigest = result.CacheKey` when `request.Package != nil`; `result.CacheKey` is `cacheKey(receiptInput(...))` = SHA-256 of the CCJ-1 wrapper `{schema_version:3,package,build}` computed before the compiler view exists, and `StoreArtifact` publishes the receipt under that same key with `LookupArtifact` enforcing `receipt.cache_key == key` and `receipt.input == input`. The package DeepEqual guard (compiler session must bind the requested package) is kept.
- Cache hit (pipeline.go:351-355) and fresh compile (pipeline.go:386-392) validate with `ValidateForDigest(request.Assurance, ExpectedDigest, buildInput.Toolchain, artifactMetadata(input, bytes))` on the source-aware arm and with the unchanged `ValidateFor(buildInput)` when `ExpectedDigest == ""` (legacy). A mismatch is `build_repository_receipt_invalid` before `StoreArtifact`.
- `closureexec.BuildSessionReceipt.ValidateForDigest` (build_session.go:135-152) preserves every check of `ValidateFor`: `Validate()` (typed receipt shape, provider execution receipt required in verified mode, runtime-control shape), assurance binding DeepEqual with the operation, toolchain identity, artifact digest; only the input identity is an explicit digest. `NewPortable/NewVerifiedBuildSessionReceiptForDigest` mint the same shapes and self-validate. `ValidateFor` and the legacy constructors are untouched.
- `install.goBuilder.Stage` (builddeps.go:255-262) mints the portable receipt against `StageRequest.ExpectedBuildInputSHA256` when set; `assuredBuilder.Stage` (assurance.go:169-176) validates the inner builder's receipt against that digest with the operation authority's binding and the session toolchain; `externalGoAdapter.Compile` (external.go:458) is the only production caller that sets the field, from `CompileRequest.ExpectedDigest`. The local go-v1 arm never sets it and keeps binding `Input.CacheKey()`, which for a package-carrying input is already the wrapper digest (buildmeta `logicalValue`), so both arms now bind `sha256(CCJ-1(receipt.input)) == receipt.cache_key`.
- Verified-mode provider builders that ignore the new field mint a compiler-view receipt and are refused by `assuredBuilder.Stage` (fail closed, typed), which is the spec's required behaviour for an implementation unable to bind the input.
