# BUG-261004-16a407 — trust-pin-overrides-strict-findings

## Change and acceptance evidence

`internal/audit/audit.go:decideWithPins` now uses a pin only to satisfy the pre-capability pin requirement. It always applies `Decide` to findings after that requirement. Revocation still blocks earlier, including pinned content. Fresh and cached findings share this decision function.

`TestGatePinPolicyFreshAndCached` drives the real production entries `Gate` and `GateReadOnly`, used by `internal/install/install.go`, `internal/install/global.go`, and the install/audit command paths in `cmd/curator/main.go`. Cache cases are populated by production `Gate` under advisory policy, then the target policy, pin, and revocation state are applied. Each case verifies the expected initial cache presence; fresh cases have no verdict before entry. No mocked decision functions or injected detector findings are used.

Coverage bound: 13 policy scenarios × 2 cache states × 2 entries = **52/52 cases passing**. Scenarios include pinned schema-3 findings at the threshold, schema-4 findings above it, pinned schema-2 findings, pinned clean schemas 1/2, unpinned schema-2 require_pin, strict/advisory revocation of pinned content, pinned advisory warnings for schemas 2/3, unpinned advisory warnings, strict below-threshold warnings, and strict fail_on=off warnings. This is the task's pin-decision matrix, not a claim about all audit detector coverage.

The proposed manager §7 sentence is attached as `BUG-261004-16a407_spec-clarification.md`. Per the latest task brief, curator-spec was not edited. The sentence is: “A pin satisfies only the pre-capability requirement; it never waives a finding at or above fail_on.”
