## 2. Why an exit code was never the semantic layer

Read from this host's Go sources, not carried forward from an earlier cycle:

- `$GOROOT/src/cmd/go/internal/modload/modfile.go` raises
  `&gover.TooNewError{...}` **after** `modfile.Parse` has returned and after
  `gover.Compare(f.Go.Version, gover.Local()) > 0` has been evaluated. The value
  was parsed and represented before the host gate could fire.
- `$GOROOT/src/cmd/go/internal/gover/toolchain.go` renders that error as
  `"%v requires go >= %v (running go %v%v)"`.
- `$GOROOT/src/internal/gover/gover.go` imports only `cmp`. Neither `Parse` nor
  `IsValid` consults the local version at all.

So upstream keeps representability and the host-version gate apart and applies
them in that order. A single exit status is their conjunction and cannot be
decomposed back.

Curator already has its own place for the host relation, which is the second
half of the argument: `go 1.99.0` against a resolved `1.23.4` is a class-2
comparison whose base triple is above the resolved version, reported as
`build_toolchain_metadata_mismatch` with a **derived canonical assertion**.
Folding the host gate into the grammar layer would classify one fact twice, under
two different payloads, and would move every representable future release into
the `unclassifiable` class.

## 3. What changed

### Probe (`.temp/TASK-260728-1g0z69/probe`, attached)

Step 2 is now an **isolated measurement**, corroborated by a **classified**
command outcome:

- *Isolated (primary).* The probe lifts `internal/gover/gover.go` whole and
  `FromToolchain` verbatim out of **the probed toolchain's own `GOROOT`**, builds
  them with that same toolchain, and evaluates `gover.IsValid(v)` for a `go`
  value and `v == "default" ∨ FromToolchain(v) ≠ ""` for a `toolchain` name.
  Nothing is transcribed by hand, so the harness cannot drift from the toolchain
  it claims to measure. Path and SHA-256 of every lifted source are printed. The
  extractor refuses to lift a `FromToolchain` that references `base.`, `fmt.`,
  `errors.` or `context.`, so a future upstream refactor fails the probe instead
  of being silently worked around.
- *Corroborating.* The real command's outcome is classified into three states —
  accepted / too-new / rejected — with too-new counting as representable.
  Too-new is recognised structurally, not by a loose grep: the probe requires the
  version the command echoes back between `" requires go >= "` and
  `" (running go "` to equal the value under test, which upstream can only
  produce by having parsed and compared it.
- The two must agree wherever the shape layer accepts the value. Where the shape
  layer rejects it, the command is measuring the conjunction and the comparison is
  reported `n/a` rather than forced.

Three new `go`-directive cases: `1.99.0` (the reviewer's), `1.26.0` (near-future,
so the property does not depend on an absurd version) and `1.99rc1` (future
prerelease). Inventory 13+13 → **16+13, 58 measured cases across two toolchains**.

The three superseded classifications are now **runnable controls in the same
binary** (`-semantic tidy-exit`, `-red patch-prerelease-compared`,
`-red c-equals-upstream`) instead of hand-edited copies, so a change that
reintroduces one is caught by a control that stops failing.

Two probe bugs found and fixed while doing this: an inherited `GOROOT` silently
collapsed a two-toolchain run into a one-toolchain run (`go version` reported
1.25.5 for both binaries), and `toolchainVersion` did not pin `GOTOOLCHAIN=local`.
