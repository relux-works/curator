## 1. Declaration and origin-trust triggers are now disjoint by input

**Finding.** Sub-step 2a asked whether a root was declared *by an admissible
origin*, so a `PATH` declaration answered "no admissible declaration" →
`unavailable`, while 2b was specified to answer `untrusted` for the same input.

**Fix.** The overlap came from 2a pre-judging origin. The rule is now written
over what the manager actually reads.

New in section 3, **declaration channels**: the manager looks for a root in
exactly two channels — `operator_config`, then `bundled` — and in no other
place. `PATH`, the environment, shims, runtime roots, project directories, and
package bytes are *not channels*: they are never searched, so a toolchain
reachable only through one of them is not declared at all and its presence on
the host is invisible. A forbidden origin therefore reaches the manager only as
**the value of a channel entry, or the state holding it**.

Stage A sub-steps (renumbered 3a/3b/3c after the platform reorder):

| Sub-step | Input it reads | Outcome |
|---|---|---|
| 3a — declaration presence | the channel map only | none → `unavailable` |
| 3b — origin admissibility | the selected entry's value + holding state; **no filesystem** | inadmissible → `untrusted`, `substep` `origin` |
| 3c — shape | the filesystem object the value denotes | bad → `untrusted`, `substep` `shape` |

Three disjoint inputs, so no input satisfies two triggers. 3b and 3c are also
disjoint from each other now — a shim *named in the value* is 3b, a shim
*discovered on disk* is 3c — rather than merely ordered.

The overlap case is stated in the algorithm text and vectored: a host with the
toolchain installed and on `PATH` and no channel entry is `unavailable` from 3a,
explicitly not `untrusted`, because there is nothing for 3a to find and nothing
for 3b to classify. `untrusted` from 3b requires a channel entry whose value
defers to `PATH` — an operator-configuration defect, matching its
`configuration` guidance class.

Channel precedence is fixed (`operator_config` before `bundled`) so exactly one
entry is selected per identifier.

New vectors 102–106; vectors 30–34 restated against the new sub-step numbers and
inputs.

## 2. A Stage-B descriptor can no longer narrow past the resolved host

**Finding.** Stage B re-evaluated the interval but only rejected an *empty*
intersection; `incompatible` was Stage A only. A host at 1.23.0 passing manifest
`at_least 1.23.0` then meeting descriptor `at_least 1.24.0` had a non-empty
intersection that excluded it, and no step rejected it before cache/compiler
work.

**Fix.** Stage B is now an ordered five-step algorithm:

1. re-compute the effective requirement including the descriptor requirement —
   empty → `build_toolchain_requirement_unsatisfiable`;
2. re-evaluate the resolved version against that interval — outside →
   `build_toolchain_incompatible`;
3. file-shape gate (see §4 below);
4. `forbidden` dispositions and value classes;
5. `compared` dispositions and value classes.

Consequences recorded explicitly:

- `incompatible` and `requirement_unsatisfiable` each get **one firing site per
  interval they can be evaluated against** — A step 7 / B step 2, and validation
  / B step 1.
- `compatibility` is deliberately *not* re-evaluated: manager-owned, unreachable
  by any package byte, resolved version unchanged, so its Stage A verdict is
  final. Stated, not left to inference.
- The descriptor's own requirement is validated during descriptor validation
  inside the acquisition audit, so `requirement_invalid` keeps its single
  validation site.
- Section 4.3's cache table gained the Stage B row.

New vectors 107–113, covering non-empty-but-unsatisfied, empty late
intersection, harmless narrowing, step-1-before-step-2, requirement-before-
metadata, `compatibility` non-re-evaluation, and local commands.

## 3. Platform applicability now precedes OS-specific resolution

**Finding.** Stage A resolved an OS-specific relpath and probed before checking
`platforms`, so on an unsupported host there was no relpath to resolve and no
probe to build — `platform_unsupported` was unreachable on exactly the hosts it
describes.

**Fix.** The check is split, and the split is forced by the registry rather than
chosen:

- New section 1.1 rule: `primary_relpath` and `probe` are declared **per
  operating system** and an entry is well-formed only when both are declared for
  every operating system in `platforms`; neither is declared outside it and
  neither has a default. Section 6.3's release gate now applies its resolution
  and reachability properties to the registry as well (new vectors 84a, 84b), so
  every host reaching past the check has a relpath and probe by construction.
- Stage A reordered: **step 2** is the host-pair check, reading only registry
  data and the host pair — no declaration, no filesystem, no probe, no package
  byte. Resolution is step 3, probe step 4, normalization step 5.
- The reported-target half necessarily follows the probe and stays at **step 6**.

One code still covers both halves; the payload's new REQUIRED `check`
discriminant (`host_pair` | `native_target`) says which fired, and it selects
the previously unlabeled either/or between `supported_platforms` and
`reported_target` + `native_target`.

Step 1 stays ahead of step 2, with the reason stated: an empty intersection is
host-independent and fails identically everywhere.

New vectors 96–101, each asserting both the code and that no later step ran.

## 4. The Go classifier no longer passes ecosystem-invalid values through

**Finding.** The shared literal grammar was a deliberate superset of Go's, so
`go 1` and `go 0` passed Stage B as permitted comparisons and were deferred to
the compiler; malformed file shapes such as a repeated `go` directive had no
fixed outcome.

**Fix, part A — grammars pinned per position.** Go does not use one grammar in
the two directive positions, so neither does Curator. Verified against the
vendored sources on this host, not from memory
(`golang.org/x/mod@v0.38.0/modfile/rule.go`,
`GOROOT/src/cmd/go/internal/gover/{toolchain,gover}.go`):

| Grammar | Position | Source |
|---|---|---|
| `goModVersionLiteral` | whole `go` directive value | `modfile.GoVersionRE` verbatim |
| `goToolchainNameShape` | whole `toolchain` directive value | `modfile.ToolchainRE` verbatim |
| `goToolchainVersion` | version part after upstream's split | the language `gover.Parse` accepts |

`GoVersionRE` requires a nonzero major and a **required** minor, so `go 1`,
`go 0`, `go 1.023`, `go 1.23rc` are now class 4 → typed
`metadata_mismatch` before cache lookup and before a compiler child.
`gover.Parse` admits a bare major, so `toolchain go1` is class 5 comparing as
`(1, 0, 0)` — not unclassifiable — and rejects a prerelease after an explicit
patch, so `toolchain go1.` (ToolchainRE-valid, `FromToolchain`-empty) is class 7.

The superset paragraph is replaced with the actual argument: the
assertion-not-selector defence is sound for *selection* and unsound for
*ordering*, because a wider grammar converts a Go-invalid file into a permitted
Curator comparison that fails later as a compiler error. Curator is now neither
wider nor narrower than upstream at either position.

**Fix, part B — one file-shape gate instead of per-classifier shape cases.**
Upstream `modfile` reports "repeated go statement" and "repeated toolchain
statement" as *parse errors*, so such a file yields no value to classify. New
Stage B step 3: a present `metadata_sources` file that the ecosystem's own
grammar rejects — including a single-occurrence directive appearing twice — is
`metadata_mismatch` with `assertion` `unclassifiable`. It precedes steps 4 and 5
by necessity: a field that cannot be extracted cannot be classified. Scope is
stated as file **syntax** only — nothing about the semantics of unread fields.

This replaces the old class-7 special case for a repeated `toolchain` and closes
the matching gap for `go`, with one rule instead of two.

New vectors 114–126; vector 53 re-attributed to the file-shape site.
