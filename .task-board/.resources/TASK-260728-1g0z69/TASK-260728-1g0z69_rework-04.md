## 1. The `go`-directive classifier is now defined over both acceptance layers

**Finding.** The reference applied `gover.Parse` only to toolchain *names*, and
defined the `go` directive by `modfile.GoVersionRE` alone. `GoVersionRE` matches
`go 1.23.4rc1`, so vector 122 classified it as class 3 — a permitted comparison
— even though the Go command cannot represent it. The value passed Stage B and
reached compiler-side work, which is the exact deferral the cycle-3 rework was
supposed to close.

**Verified first, from this host's own sources and toolchains — not from the
prior cycle's claims.** `$(go env GOROOT)/src/cmd/vendor/golang.org/x/mod/modfile/rule.go`
line 329 is `GoVersionRE`; `src/internal/gover/gover.go` `Parse` returns the
zero version when a prerelease follows an explicit patch, with the upstream
comment giving the reason (`1.21.3rc1 < 1.21.3` would order opposite to
`1.21 < 1.21rc1`). Measured on Go 1.25.1 and Go 1.25.5:

| `go` line | `go mod edit -json` | `go mod tidy` |
|---|---|---|
| `1.23`, `1.23.4`, `1.23rc1` | exit 0 | exit 0 |
| `1.23.4rc1`, `1.24.0alpha1`, `1.21.3beta2` | **exit 0** | **exit 2 — `panic: go: internal error: missing go root module`** |
| `1`, `0.1`, `1.023`, `1.23rc`, `v1.23`, `1.23/4` | exit 1 | exit 1 |

**Fix.** Section 4.2.1 no longer names one grammar per position. It names the
two **layers** Go actually composes, and pins both:

| Layer | Artifact | Decides |
|---|---|---|
| shape | `modfile.GoVersionRE` / `ToolchainRE` | whether `go.mod` parses |
| semantic | `internal/gover.Parse`, `gover.FromToolchain` | whether the command can *represent* what it parsed |

Upstream acceptance in a position is the **conjunction**. The two layers are
incomparable in both positions — the shape layer accepts `1.23.4rc1`, the
semantic layer accepts a bare `1` — so neither alone is the language, and the
conjunction is strictly smaller than either. Grammar names changed to match:
`goModVersionLiteral` → `goModVersionShape`, `goToolchainVersion` →
`goSemanticVersion` (the same language, now correctly applied at both
positions).

`go`-directive class 4 is therefore the complement of the conjunction, reached
two ways — shape-layer rejection and semantic-layer unrepresentability — with
one code, one `assertion` token, and one firing site, because the distinction
does not change what a caller can do.

Vector 122 is replaced (class 4, `assertion` `unclassifiable`, explicitly not a
class-3 comparison) and joined by 122a `1.24.0alpha1`, 122b `1.21.3beta2`, 122c
layer attribution against a repeated directive, and 122d `1.23rc1` staying
permitted so the narrowing is confined to the patch-prerelease region. Vector
118 is restated as the opposite half of the boundary. The `toolchain` classifier
gains 124a `go1.99.0rc1x`.

**Why this is a classifier case and not the file-shape gate.** The gate's stated
scope is file *syntax*, and its premise is that a file yielding no value has
nothing to classify. `go 1.23.4rc1` parses and its field extracts; what rejects
it is version *semantics*. Routing it to the gate would falsify the gate's own
scope statement. Section 5's firing-site list now states the split explicitly:
file grammar at B step 3, value semantics at B step 5, no input at both.

## 2. Vector 126's equality is replaced by two satisfiable properties

**Finding.** Vector 126 required the `compared` set to equal the upstream-accepted
set for both directives. Upstream accepts `go1.21.0-custom`; this contract
classifies custom-distribution names as `forbidden`. The sets cannot be equal,
so the vector was unsatisfiable rather than merely strict.

**Fix.** New section 4.2.1.1 states the alignment as two properties over the
classifier's partition `C` (compared), `F` (forbidden), `U` (unclassifiable):

- **P1, no widening:** `C ⊆ Upstream` — nothing Go rejects is permitted as a
  comparison.
- **P2, no narrowing outside the security partition:** `Upstream \ F ⊆ C` — no
  Go-valid, non-forbidden value is failed for a grammar reason.

Together `C = Upstream \ F`. `F` appears in P2 and in neither side of P1, which
is what makes both satisfiable. The section also records why the naive equality
cannot be recovered by adjusting `F`: `F` is *neither* a subset of nor disjoint
from `Upstream` — `go1.21.0-custom` is in both, `go1.23/../evil` is forbidden
and upstream-rejected — so only `C` is pinned, and it is pinned exactly. For the
`go` directive `F` is empty, so P2 collapses to `C = Upstream` there.

Vector 126 becomes P1; 126a is P2 with the exclusion stated; 126b asserts the
partition genuinely subtracts (`go1.21.0-custom` upstream-admitted *and*
forbidden), which is the fact that makes the equality unsatisfiable; 126c
asserts `F ⊄ Upstream`; 126d asserts `F` is empty for the `go` directive.

## 3. The executable probe

New section 4.2.1.2 makes the probe a normative obligation rather than a
one-off: measure each layer independently per value, derive acceptance as the
conjunction, fail on disagreement with a classifier table, fail on a P1 or P2
violation, and fail if a position's `forbidden` partition does not subtract at
least one upstream-admitted value. Offline, no named toolchain installed
required, re-run before a new Go release family enters `compatibility`.

The probe is implemented and run: `.temp/TASK-260728-1g0z69/probe/` (Go, no
dependencies), 13 `go`-directive and 13 `toolchain`-directive values × Go 1.25.1
and Go 1.25.5, **exit 0, 0 divergences**. Layer measurement is
`go mod edit -json` (shape), `go mod tidy` (`go`-directive semantics), and
`GOTOOLCHAIN=local+path` (`toolchain`-directive semantics, offline — a
representable name yields `cannot find "X" in PATH`, an unrepresentable one
yields `invalid toolchain "X" in go.mod` before any search).

The probe lives in the task's `.temp` rather than in the spec repo because the
conformance suite, vectors, and tooling belong to `TASK-260728-2jaw7h`; decision
0007's downstream obligations now name landing it there, and require each
reserved-toolchain task to identify its own ecosystem's layers and extend the
probe rather than assert a disposition table from one artifact's grammar.
