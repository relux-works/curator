# TASK-260906-3x0w4y: path-overlay-cannot-be-declared

## Description
environments.md section 6 permits an overlay named by a path source, and section 1 plus the section 12.1 knob shape and the manager-config-v2 overlay schema together make such an overlay impossible to declare. Reconcile them so a path overlay has a declaration, without weakening the section 1 rule that a path declaration carries no requirement form.

## Scope
Established by reading the sources at 550579d. environments.md section 6: an overlay is an ordinary context package named by a git source with a range or exact form, or by a path source under the section 1 rules. environments.md section 1, path kind: A path declaration that carries range, tag, branch, revision, or directory is profile_source_invalid, and a path package serves as a profile root or as an overlay (section 6). environments.md section 12.1 knob table: overlays.<profile> is an ordered list of { source, range | tag | revision, directory?, weight? }, which mandates a form on every overlay. schemas/v1/manager-config-v2.schema.json $defs/overlay carries oneOf [required range, required tag, required revision], mandating the same. conformance/v1/schema-cases/manager-config-v2/*.json publish an overlay whose source is /Users/operator/context carrying a revision, which section 1 makes profile_source_invalid. Downstream evidence: stage (c) review finding M1 drove all three production surfaces in curator and found no operator can declare a path overlay; the only passing test builds a Policy in Go that PolicyFromConfig cannot produce.

## Acceptance Criteria
A path overlay is declarable: the 12.1 knob row and the manager-config-v2 overlay schema require a requirement form only for a git source and accept a path source carrying none, while a path overlay carrying range, tag, branch, revision or directory stays profile_source_invalid. The published schema cases and vectors stop giving a path source a revision, and gain a positive case for a form-free path overlay and a negative case for a path overlay carrying a form. make validate and make regenerate-check green. Any case the pinned Go manager consumes stays passable by that pin.
