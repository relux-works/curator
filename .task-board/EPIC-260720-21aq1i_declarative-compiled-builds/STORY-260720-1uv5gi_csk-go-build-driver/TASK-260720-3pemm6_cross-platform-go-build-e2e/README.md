# Add cross-platform Go build end-to-end tests

## Description
Add a minimal real Go skill fixture and end-to-end tests that prove csk can install, cache, activate, launch, repair, and roll back compiled commands on the rc.5 supported platforms, macOS and Windows, while Linux CI keeps portable non-driver coverage only.

## Scope
Own new cocoaskills test fixtures, end-to-end and process-level tests, and .github/workflows/ci.yml changes needed to select the operator-trusted accepted Go release family recorded in the protocol and Curator handoff evidence, family 1.25 in the currently accepted Curator implementation with Go 1.23 as the protocol floor only, and to run the exact rc.5 candidate suite without advancing the default committed curator-spec release pin. Real-fixture go-v1 build, cache, activation, launch, repair and rollback coverage runs on native macOS and native Windows runners. The ubuntu jobs keep running portable non-driver coverage such as models, CCJ-1, POSIX cache, locks and transactions, and shims, and must assert that the source-aware go-v1 path fails closed there rather than producing a green build. Cross-platform candidate qualification may accept an explicit immutable curator-spec revision or pre-materialized CURATOR_CONFORMANCE_ROOT as a non-default caller input, and must record its full manifest digest. Exercise project, global, hybrid, mixed script and build commands, and platform shims with real subprocesses. Use injected failures and fake toolchains only for negative paths. Linux go-v1 driver qualification is out of scope and stays with TASK-260728-1skseh and TASK-260728-1e6811. Do not change product semantics except narrowly scoped testability hooks routed to owning tasks; the released-suite pin belongs to TASK-260720-1utsx8 after TASK-260720-25d05o.

## Acceptance Criteria
A valid vendored Go command builds without network under the portable manager-worker-v1 policy, launches only after explicit invocation, receives exact forwarded arguments, returns its exit status, and works through project and global shims on macOS and Windows. Tests prove cache hit without go list or go build, rebuild on source, toolchain, target, execution-policy, receipt or artifact change, no rebuild on irrelevant mode or timestamp change, dry-run byte purity, build-two failure isolation, target-swap rollback, interrupted recovery, identical concurrent publisher handling, and two-project consumer preservation. Native macOS and native Windows jobs run the real fixture across the supported Python matrix with explicit accepted-family Go setup and an exact caller-supplied candidate-suite revision or root whose manifest digest is recorded as non-release evidence. Ubuntu jobs run portable non-driver coverage across the same Python matrix, prove the source-aware go-v1 path fails closed with an unavailable-control error and no worker launch, and neither require nor claim a green go-v1 build; Linux driver success is not asserted anywhere. Per-platform capability evidence matches rc5-native-control-inventory-v1 exactly on each native runner. CI preserves the previous released default pin and has no unexpected skip or xfail. Full relevant pytest and strict mypy pass.
