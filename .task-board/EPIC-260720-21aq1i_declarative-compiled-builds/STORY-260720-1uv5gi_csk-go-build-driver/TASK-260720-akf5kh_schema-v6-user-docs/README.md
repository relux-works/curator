# Document schema v6 compiled commands

## Description
Update English source documentation and maintained Russian mirrors so authors and operators can use csk schema 6 under the rc.5 portable manager-worker-v1 execution policy without inferring build, cache, security, platform, status, repair, or activation behavior from code.

## Scope
Own README.md and README.ru.md, ARCHITECTURE.md and ARCHITECTURE.ru.md, SECURITY.md and SECURITY.ru.md, docs/skill-authoring.md, CHANGELOG.md, and directly related link or documentation tests. Include one complete mixed schema 6 example, fixed go-v1 prerequisites and limits, the portable manager-worker-v1 execution boundary, csk-specific manager-home build-cache layout, logical portability boundary, build-root context exclusion, lifecycle and dry-run ordering, status and reinstall repair, GC, and Unix and Windows command resolution. Document the supported-platform claim as macOS and Windows only, with Linux explicitly deferred and named owners. Maintain the README tool and validation command section. Do not claim releases, tags, pins, signatures, reviews, or interoperability evidence that do not yet exist, and do not document any deferred hardened guarantee as provided.

## Acceptance Criteria
Documentation explains the vendor-only requirement and the Go family rule honestly: protocol core.md sets a Go 1.23 floor, and csk accepts only the operator-trusted release family recorded in the protocol and Curator handoff evidence, which is family 1.25 in the currently accepted Curator implementation. It documents native target, private telemetry off, cgo, PGO, workspace, generator, external-link and network prohibitions, no arbitrary args or hooks, and why other drivers fail closed. It documents the portable manager-worker-v1 execution policy as a normative cache, receipt, marker and claim input rather than an option or operator preference: the fixed four-node process graph of manager parent, identity-verified manager-owned worker, fingerprinted GOROOT/bin/go and fingerprinted GOROOT/pkg/tool children, pre-launch and post-exec identity verification, frozen snapshot integrity, worker-domain teardown, and the never-run artifact rule. It documents capability evidence honestly: one capability-evidence-v1 record per operation, one entry per rc5-native-control-inventory-v1 control, and the real per-platform availability, including that active-process-count-limit and aggregate-memory-limit are available on Windows through job objects but unavailable on macOS, and that per-file-size-limit is available on macOS through rlimit-fsize but unavailable on Windows. It states that an unavailable inventory control does not reject a build while a missing mandatory portable control does, and it never presents any of the six deferred hardened guarantees as provided. It states the supported platforms as macOS and Windows, explains that source-aware go-v1 fails closed elsewhere, and records Linux as explicitly deferred with owners TASK-260728-1skseh and TASK-260728-1e6811 rather than as unsupported by accident. It distinguishes installed content hashes from build-source identity and receipt consistency from protected-state provenance. It documents project, global, and hybrid transaction rollback, compiler-free dry-run outcomes, status --json and --check, reinstall repair, locked GC, and direct project/global shim resolution on Unix and Windows. English and maintained Russian files agree, local links resolve, examples parse, documentation tests pass, and strict mypy remains green.
