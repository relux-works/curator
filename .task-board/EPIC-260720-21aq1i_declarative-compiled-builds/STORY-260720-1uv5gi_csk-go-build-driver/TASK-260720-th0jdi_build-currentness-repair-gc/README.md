# Implement build currentness, repair, and GC

## Description
Extend project and global status, install repair behavior, and locked garbage collection to understand marker v2, protected build entries, receipts, artifacts, raw source identity, current toolchain, target and execution policy, and in-flight journals.

## Scope
Own src/csk/status.py, build-currentness helpers, src/csk/gc.py, global status integration, and focused CLI and maintenance tests. Keep marker v1 currentness for schema 1 through 5. For v2 builds, inspect the selected raw snapshot and static context boundary, recompute logical identities including the rc.5 policy.execution_policy member, verify protected-state provenance and receipt and artifact bytes, and confirm marker and shim references. Execution-policy mismatch is a currentness and rebuild dimension; it is already covered transitively by the complete cache-key and receipt comparison, so state it explicitly rather than adding a separate mechanism. Capability evidence is result-only and is never a currentness input. A normal install is the csk repair operation; do not invent a separate package-controlled repair hook.

## Acceptance Criteria
Status reports up-to-date only when ref, installed content, build roots and context exclusion, build source, toolchain, target, execution policy, cache key, protected boundary, canonical receipt, artifact path, hash and size, marker build fields, and managed shim agree. A build recorded under a cache key that does not carry policy.execution_policy = manager-worker-v1, including the legacy key sha256:3fcd714a40e8918eb67dbd35d435875dcce6c9047da811a1fa26626e5e57be48 and the reserved-hardened key sha256:13736230d33ce59de7f7323dcd4cffd510655ad8dabd5ee9e8b6cb182ec70037, is non-current and is rebuilt rather than adopted. Missing, corrupt, wrong-target, wrong-toolchain, wrong-policy, unsupported, context-leaking, or untrusted build state is non-current in text and JSON and makes --check fail. Capability-evidence records are surfaced in status output but never change the currentness verdict. Reinstall rebuilds or repairs from a revalidated snapshot without adopting untrusted bytes. GC runs under the home lock, marks keys from valid marker v2 files and active journals across project, global, and hybrid stores, retains uncertain state conservatively, and sweeps only unreferenced protected entries after the grace rule while preserving runtime and snapshot GC compatibility. Focused status, global status, repair, GC, corruption, provenance, and strict-mypy gates pass.
